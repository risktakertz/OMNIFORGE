# AGENTS.md — coding-agent instructions for the OMNIFORGE repository

This file tells any authorized coding agent (Codex, OpenCode, Claude Code, OpenHands,
Copilot Workspace, or a human contributor) how to work inside OMNIFORGE without
breaking its guarantees. The primary Agent Skill entry point lives at
`skills/omniforge/SKILL.md`; this file is the repository-level contract.

## What this repository is

OMNIFORGE turns short, ordinary, nontechnical requests into original, working,
tested, exportable software. It is a pnpm + Turborepo TypeScript monorepo with a
deterministic, free-first core: intent parsing (English + Swahili), product
blueprints, a validated Agent Skills capability registry, hybrid skill routing,
a LangGraph orchestration graph with durable checkpoints, a policy tool gateway,
isolated project workspaces, verification with evidence, and an exportable CLI
(`omniforge`).

## Non-negotiable rules for agents working here

1. **Never fork upstream repositories** and never copy upstream source trees into
   this repository. Add integrations as dependencies, CLI adapters, MCP endpoints,
   or documented specs in `integrations/`, and record them in
   `integrations/catalog.yaml` + `integrations/lock.json`.
2. **Never commit secrets.** Credentials go in `.env` (git-ignored) or an approved
   secret store. `.env.example` lists variable names with dummy values only.
   If you find a secret, do not echo it into logs, tests, or documentation.
3. **Never claim a capability is verified when it is not.** Status vocabulary is
   `verified | configured | unavailable | blocked | untested` (see
   `packages/shared-types`). Unavailable outcomes must surface a typed gap, not a
   simulation.
4. **Free-first economics.** `FREE_FIRST_MODE=true`, `AUTO_PROVISION_PAID=false`,
   `APPROVED_SPEND=0`. Never trigger billable actions without explicit approval.
5. **Destructive operations require approval** through the policy gateway
   (`packages/tool-gateway`). Never `rm -rf` outside known generated artifacts,
   never force-push, never modify repositories other than this one.
6. **Write only inside the selected workspace.** Filesystem writes must stay within
   the project workspace and approved temp dirs; the gateway enforces this.
7. **Generated client products are isolated.** Work happens under `projects/`
   (git-ignored). Template changes must not mutate previously delivered projects.
8. **Testing is evidence.** A task is complete only when a reproducible check
   passes and its `Evidence` record exists. Do not delete assertions to make
   tests pass; do not hardcode results.

## Common operations

```bash
pnpm install                 # bootstrap (corepack/pnpm 9)
pnpm verify                  # lint + typecheck + test + build + e2e
pnpm omniforge doctor        # environment/capability report
pnpm omniforge plan "..."    # read-only intent, blueprint and cost plan
pnpm omniforge create "..."  # build a product into projects/
node scripts/gen-skills.mjs  # regenerate skill packs after editing the table
```

## Where things live

- Product contracts: `packages/shared-types`
- Request interpretation: `packages/intent-engine` (English + Swahili lexicons)
- Blueprint/acceptance specs: `packages/blueprint-engine`
- Skill discovery/validation: `packages/capability-registry`
- Routing policy: `packages/skill-router`
- Graph orchestration: `packages/orchestration` (LangGraph.js + durable checkpoints)
- Policy gateway: `packages/tool-gateway`
- Workspaces/locks/export: `packages/workspace-manager`
- Verification/repair classification: `packages/verification`
- CLI: `apps/cli` (command `omniforge`)
- Skill packs: `skills/` (generated by `scripts/gen-skills.mjs`)
- Integration specs and licenses: `integrations/`
- Product templates: `templates/`
- Acceptance + adversarial tests: `tests/`

## Source of truth

OpenSpec-style specs, blueprints, and acceptance criteria are the single source of
truth for what to build; gstack/Superpowers are advisory methodologies. Do not
introduce a second orchestration engine. When this file conflicts with verified
behavior, fix the code or the file — never paper over it.
